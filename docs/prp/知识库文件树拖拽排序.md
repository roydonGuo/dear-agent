# 知识库文件树拖拽排序 — 实现方案

## Context

当前知识库文件模块已支持树形结构（`parentId` + `ancestors`）和文件/文件夹的 CRUD，但缺少排序能力。树构建时仅按 `createTime DESC` 排序，前端无法调整节点顺序。需求是：前端文件树支持拖拽排序，允许跨层级拖拽（改变父子关系），排序控制权在后端。

## 涉及模块

- `module-knowledge` — 领域实体、服务、DTO
- `module-web` — Controller 层
- 数据库 — `ai_knowledge_file` 表

**新建 `ReorderRequest.java`** — 拖拽排序请求 DTO：
```java
@Data
public class ReorderRequest {
    @NotNull private Long id;              // 被移动的节点ID
    @NotNull private Long targetParentId;   // 目标父节点ID（0=根目录）
    @NotNull private Integer position;      // 目标位置索引（0-based）
}
```

### 3. Service 层

**`IKnowledgeFileService.java`** — 新增接口方法：
```java
void reorder(Long baseId, ReorderRequest request);
```

**`KnowledgeFileServiceImpl.java`** — 核心改动：

#### 3.1 树构建排序（`buildTree` 方法）
- 查询改为 `orderByAsc(KnowledgeFileDO::getSort).orderByDesc(KnowledgeFileDO::getCreateTime)`
- `buildChildren()` 中不再依赖 grouped map 的无序迭代，改为显式排序

#### 3.2 新增节点默认 sort 值
- 在 `save()` 方法中：若 `sort == null`，查询同父级最大 sort 值 + 100，或默认 0

#### 3.3 拖拽排序核心逻辑（`reorder` 方法）

排序策略：**整数间隙法**，步长 100。

```
reorder(baseId, request):
  1. 获取被移动的 node
  2. 校验 baseId 归属
  3. 校验：不能将文件夹移动到自己的子孙节点下（循环引用检查）
     - 若 node 是 folder 且 targetParentId 的 ancestors 包含 node.id → 拒绝
  4. 获取目标父级下所有子节点（排除自身），按 sort ASC 排序
  5. 将 node 插入到 position 位置
  6. 为所有兄弟节点重新分配 sort 值：100, 200, 300...
  7. 若 parentId 变更：
     - 更新 node.parentId = targetParentId
     - 重新计算 node.ancestors
     - 若 node 是 folder → 递归更新所有子孙的 ancestors
  8. 批量更新/保存
  9. 清除树缓存 evictTree(baseId)
```

循环引用检测逻辑：
```
if node.type == "folder":
    targetAncestors = getById(targetParentId).ancestors  // "0,1,5"
    if targetAncestors.split(",") contains node.id → 拒绝
```

### 4. Controller 层

**`KnowledgeFileController.java`** — 新增接口：

```java
@PutMapping("/reorder")
@Operation(summary = "拖拽排序", description = "移动节点到目标父级下的指定位置，支持跨层级拖拽")
public BaseResult<Void> reorder(@RequestParam Long baseId, @Valid @RequestBody ReorderRequest request)
```

- 调用 `knowledgeFileService.reorder(baseId, request)`
- 清除树缓存
- 返回成功

### 5. MapStruct

`KnowledgeFileConvertor` — 无需改动，字段名一致会自动映射。

## 拖拽场景覆盖

| 场景 | 示例 | 处理 |
|---|---|---|
| 同级内移动 | 文件A从位置0拖到位置2 | 仅更新兄弟节点的 sort |
| 跨父级移动 | 文件A从 folder1 拖到 folder2 | 更新 parentId + ancestors + sort |
| 文件夹跨级 | folderA 从 folder1 拖到 folder2 | 更新自身 + 递归所有子孙的 ancestors |
| 移入根目录 | 节点拖到根 | targetParentId=0，ancestors="0" |
| 循环引用 | 把 folder1 拖入它的子文件夹 | 拒绝操作 |
| 拖到末尾 | position >= 兄弟节点数 | clamp 到末尾 |

## 验证方案

1. **单元验证**：直接调用 `buildTree()` 确认子节点按 sort 排序
2. **接口验证**：用 curl/Postman 验证 reorder 接口
    - 同级拖拽 → 确认 sort 值更新，树顺序正确
    - 跨级拖拽 → 确认 parentId、ancestors 全部更新
    - 循环引用 → 确认返回错误
3. **缓存一致性**：拖拽后确认树缓存已清除，下次查询返回最新结构
4. **前端联调**：拖拽后用 `GET /knowledge-file/tree?baseId=xxx` 验证顺序
